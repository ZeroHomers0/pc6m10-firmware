### 2.2 代码完整性盘点（缺失 5 大类）

| 缺失项 | 影响 | 优先级 |
|---|---|---|
| 数据段（字符串、查表、RAM 初始值） | 反编译引用裸地址无内容，链接不过 | 最高（清单已导出→`DATA_SEGMENT_2026-08-21.md`；RAM 初始镜像/位域待收尾） |

| 函数原型类型（参数/返回值） | 大量 `undefined4`/`void` | 中 |
| 外设寄存器定义（CMSIS/LPC176x 头文件） | 全工程裸地址，无 volatile 语义 | 高 |
| 工程文件（IAR .ewp/.icf、向量表、启动文件） | 无法构建 | 高 |

### 2.3 可编译性评估（当前不能编译，原因）

1. `DAT_0000xxxx` 符号无任何声明。
2. 无外设寄存器头文件；Ghidra 反编译丢失 volatile/访问宽度/对齐语义，行为无保障。
3. 依赖 IAR 运行时（`iar_init_core`/`__iar_program_start`），无真实 IAR 库与启动文件。
4. 数据段（字符串、常量表、初始 RAM）完全缺失。
5. `*DAT_xxxx`（DAT 存指针再解引用）类模式需人工核对访问宽度，否则行为错误。

## 4. 优化还原方向（目标 B 的技术路径）

从"反编译转储"走向"可编译源码"的必由之路，按回报排序：

1. **数据结构优先**：还原参数银行（0x10002A0C 区）、状态机枚举、菜单表 →
   300 多处 `DAT_0x48D8` 变成 `event_code`，可读性陡增。
2. **全局变量语义命名**：按模块重命名（`uart3_rx_state`、`scr_fire_angle`、`pid_accum`），回报最高。
3. **常量表落地**：波特率表/PID 表/软起表/字符串导出为 `const` 数组与 `#define`。
4. **寄存器访问封装**：建立 `reg.h` 提供 `FIO0SET`、`U3THR` 等宏，裸地址变驱动调用。
5. **大函数拆分**：state_machine 按事件码拆成 `state_menu_run()`、`state_param_edit()` 等子函数。
6. **逐函数回验**：每次改型后对照 `.txt` 反汇编确认指令序列不变（等价性锚点）。

## 6. 风险与注意事项

- 反编译还原固件即使全部编译通过，**不能保证与原始 bin 逐字节一致或行为 100% 等价**——
  编译器版本、优化级别、链接布局均不同。
- 可接受标准应为"**功能等价**"，最终靠硬件验证，非静态分析可证明。
- Ghidra 反编译的 `*DAT_xxxx` 指针模式、访问宽度、volatile 缺失是行为偏差高发点，须人工核对。
