# PC6M 人工可读化二阶段重构计划

日期：2026-09-04

基线分支：firmware-readability-2026-09-04

基线提交：fb7003b

## 1. 目标与执行原则

本计划用于继续把 PC6M 固件整理为接近人工设计和编写的嵌入式 C 工程，同时严格保持
原固件行为等价。

执行原则：

- 只改善结构、命名、类型、接口和可维护性，不主动修改产品逻辑。
- 原始 BIN、反汇编、历史文档和地址证据继续保留。
- 人工可读化约束当前固件源码、公共头文件、测试和正式工具入口。
- 每个阶段独立提交，必须通过对应测试后才能进入下一阶段。
- 不要求生成固件与原 BIN 字节完全相同，但要求状态、内存、外设和协议行为等价。
- 未经明确授权，不执行硬件烧写。

实施前主要剩余问题：

- state_machine.c 约 1765 行，output_stage.c 约 1258 行，多个函数职责过多。
- 状态与参数头文件约有 693 个地址宏，存在同地址多语义别名。
- 业务代码仍直接使用 GPIO 偏移、字符串地址、状态编号和按键编号。
- firmware_api.h 集中了几乎所有模块接口，模块边界不清晰。
- stub.c 和 func_0x0000aed0 兼容符号仍带有逆向阶段痕迹。
- 部分测试注释仍使用 DAT、g_ 等旧名称。
- 构建仍关闭了部分警告，尚无统一格式规范。

## 2. 接口与类型设计

### 2.1 领域类型

新增统一领域类型头文件，定义但不直接存储以下枚举：

- KeyCode：确认、增加、减少、退出、启动、停止、快加、快减等输入事件。
- UiScreenId：主页面、基本参数、保护参数、通信参数、PID、统计和认证页面。
- ControlMode、StartMode、FeedbackMode、ParityMode。
- RunState、OutputState、ParameterSyncState。
- FaultFlags：为各故障位提供命名掩码。
- ModbusFunctionCode、ModbusRegisterAccess、ParameterStorageWidth。

枚举只用于函数参数、局部变量和比较表达式。SRAM 映射仍使用明确的 uint8_t、
uint16_t 或 uint32_t，避免编译器改变存储宽度。

### 2.2 模块接口

将当前集中式 firmware_api.h 拆分为按职责组织的接口：

- 系统启动与调度；
- 输入与按键；
- 显示；
- 参数与 EEPROM；
- UART 与 Modbus；
- 输出与保护；
- 闭环控制。

firmware_api.h 保留为可选汇总入口，新业务模块只包含自己实际依赖的头文件。仅跨模块
调用的函数公开，其余函数改为 static。

### 2.3 地址访问规则

- 建立唯一的底层地址映射层，集中保存绝对地址、寄存器偏移和访问宽度。
- 每个物理地址指定一个规范名称；同地址不同业务视图必须注明别名原因。
- 业务层通过命名状态、内联访问器或驱动接口访问，不直接出现裸地址。
- volatile、读写次数、读改写顺序及 8/16/32 位访问宽度不得改变。
- 禁止动态内存、标准库状态、额外持久全局变量和未经验证的缓存。

## 3. 分阶段实施

### 阶段 0：冻结基线与增加护栏

- 记录当前 ELF 尺寸、段布局、公开符号、地址映射和 25/25 测试结果。
- 增加静态检查，禁止在活动源码中重新引入 DAT_、PTR_、g_、undefined、iVar、
  local_ 和未经说明的 func_0x 名称。
- 为历史证据、迁移脚本和反汇编目录建立明确豁免范围。
- 修正读宽验证器对“同一地址存在多种语义视图”的识别。
- 当前读宽报告中的差异必须逐项归类为真实错误、合法别名或验证器误报。
- 最终要求读宽报告不存在未解释差异。
- 验收：不改变业务行为，构建和完整测试仍通过。

### 阶段 1：常量、状态和输入事件语义化

- 用 KeyCode 替换 1、2、3、4、5、6、0x16、0x21、0x17、0x0E 等按键数字。
- 用 UiScreenId 替换 0x0A、0x62、0x63、0x5A、0x1E 等页面编号。
- 将超时、采样次数、角度、寄存器号、GPIO 位和故障位整理为带单位的常量。
- 将字符形式的状态比较改为命名枚举值。
- 字符串 Flash 地址改为命名 StringId 常量，继续由 strpool_map() 完成原地址映射。
- 验收：状态机调用轨迹 100/100、跨拍矩阵 222/222、输入扫描全部通过。

### 阶段 2：硬件访问层

- 在 reg.h 中完善 GPIO、TIMER、UART、ADC、PINSEL 和系统控制寄存器结构。
- 用命名寄存器成员替换 base + 0x18、timer[6] 等裸偏移。
- 为 GPIO 设置、清除、方向配置提供 static inline 操作，名称直接体现端口、引脚和用途。
- UART 波特率配置拆成“波特率索引选择”和“UART 除数写入”两个明确步骤。
- ADC、I2C 和 LCD 只通过各自驱动接口访问寄存器。
- ISR 中只允许使用经过反汇编确认可内联的访问器，避免增加调用开销或改变写入顺序。
- 验收：外设叶函数轨迹 45/45，中断交错序列、UART 序列、ADC 序列和延时结构测试通过。

### 阶段 3：模块边界与 stub 收尾

- 将 uart3_receive_frame() 移入 UART 模块。
- 将 freq_adjust_sync() 移入参数或控制模块。
- 测试改用语义符号后，从公共接口删除 func_0x0000aed0。
- 当 stub.c 为空时删除该文件，并同步三个构建入口。
- 将仅在单文件使用的函数、常量和地址别名改为文件私有。
- 验收：ELF 不再导出无业务意义的 func_0x 符号；UART、参数同步和完整测试通过。

### 阶段 4：状态机拆分

将 state_machine() 拆为以下稳定层次：

1. 公共节拍、背光、故障和运行状态处理；
2. 根据 UiScreenId 分发页面；
3. 每个页面独立处理输入、编辑、绘制和超时；
4. 参数增减、范围钳制、页面导航和 EEPROM 请求使用公共辅助函数。

实施要求：

- 每个页面处理函数只负责一个页面。
- 保持原分支执行顺序、提前返回位置、LCD 调用顺序和 EEPROM 写入顺序。
- 第一轮只拆函数，不把全部页面立即改成数据表。
- 第二轮只对已经证明结构相同的参数页面引入页面描述表。
- 特殊页面、认证流程和运行主页面继续使用明确代码。
- 单个普通页面函数目标不超过 150 行；主分发函数目标不超过 100 行。
- 验收：case3 编辑 256/256、状态机调用轨迹 100/100、跨拍矩阵 222/222 全部一致。

### 阶段 5：参数、EEPROM 与 Modbus 数据驱动化

定义参数描述结构，至少包含：

- 参数标识；
- 实时值地址；
- EEPROM 镜像地址；
- 存储宽度；
- EEPROM 高低字节寄存器；
- 最小值、最大值；
- 是否需要同步；
- 可读、可写权限；
- 特殊写入回调。

实施方式：

- 普通参数通过描述表统一完成读取、校验、写入和同步。
- 增益组切换、运行时间清零、继电器控制等特殊寄存器保留独立处理函数。
- EEPROM 同步循环必须保持当前参数顺序和高字节先写、低字节后写的顺序。
- Modbus 描述表只替代重复分支，不改变异常码、响应长度、CRC 和帧发送顺序。
- 验收：EEPROM 同步矩阵 280/280、Modbus 分发 24/24、读寄存器 65/65、
  写寄存器 12/12。

### 阶段 6：输出级、保护与中断拆分

将 output_stage() 拆为：

- 调度节拍；
- 运行模式选择；
- 过压、欠压、过流和缺相保护；
- 软启动与软停止；
- 闭环目标计算；
- 触发角和周期计算；
- 输出状态提交。

中断部分：

- EINT1/2/3 分别保留独立入口。
- TIMER1/2 保留原寄存器写入顺序。
- 公共逻辑只允许使用 static inline 辅助函数。
- 每次改动检查生成反汇编，确认没有引入不可接受的 ISR 调用和额外 volatile 访问。
- 验收：闭环测试、继电器状态机、中断写序列、外设轨迹及输出级既有矩阵全部通过。

### 阶段 7：显示、输入和注释整理

- 为显示坐标、高亮属性、数值格式和单位建立明确类型与常量。
- 合并重复的数字渲染逻辑，但保持字符写入次序。
- 将输入消抖整理成带名称的计数器状态，不使用通用 counter_a/b。
- 源文件头注释只保留模块职责、硬件约束和关键时序。
- 反汇编地址、历史提交和验证过程移入分析文档，不在业务函数中大段重复。
- 清理测试中的 DAT、g_ 等旧注释，改为语义名称加绝对地址。
- 验收：LCD、输入扫描 512 组合及全部 A/B 测试通过。

### 阶段 8：统一代码风格与编译警告

- 新增 .clang-format：LLVM 基础、2 空格缩进、100 列、K&R 大括号、右侧指针对齐，
  不自动重排硬件相关 include。
- 新增 .editorconfig：UTF-8、LF、文件末尾换行、删除行尾空格。
- 格式化范围仅限活动 C/H 源码，不处理原始反汇编、生成字符串表和历史证据。
- 启用 -Wextra、-Wshadow、-Wstrict-prototypes、-Wmissing-prototypes 和 -Wundef。
- 在修复对应源码后移除 -Wno-unused-variable、-Wno-unused-but-set-variable 和
  -Wno-pointer-sign。
- 构建脚本共享同一份编译选项定义，防止 Makefile、Shell 和 PowerShell 参数漂移。
- 验收：零编译警告、零格式检查错误、完整测试通过。

## 4. 测试与阶段门禁

每个阶段必须执行：

~~~text
pwsh -NoProfile -ExecutionPolicy Bypass -File firmware/build.ps1
python test/run_tests.py
python tools/verification/verify_firmware_equivalence.py
python tools/verification/verify_periph_xref.py
python tools/verification/verify_readwidth_all.py
git diff --check
~~~

固定验收条件：

- test/run_tests.py 保持 25/25，新增测试只能增加总数。
- .data 保持 0，.bss 保持 2188，SRAM 初始化镜像和栈地址不变。
- 不新增未解释的 SRAM 或外设地址。
- 不出现访问宽度变化、指针元素缩放或错误的指针自增表达式。
- UART、EEPROM、LCD 和 GPIO 的可观察写入顺序不变。
- 状态机页面、参数范围、故障位、Modbus 帧和 CRC 行为不变。
- 若生成代码大小变化，必须记录原因；固件仍需满足 256 KiB Flash 布局。
- 对 ISR、延时和 SCR 触发路径的修改必须附带反汇编或轨迹对比。
- 每个阶段独立提交，不把格式化与逻辑拆分混入同一提交。

## 5. 提交与回滚策略

- 每个阶段开始前从最新已验证提交创建对应分支。
- 每个提交只包含一个可说明、可验证、可回滚的结构变更。
- 先提交测试或护栏，再提交对应重构。
- 大规模格式化必须使用独立提交。
- 任一等价测试失败时停止后续阶段，先定位到具体提交和具体模块。
- 不使用覆盖历史的 Git 操作，不删除已有证据提交。

建议阶段提交顺序：

1. readability-guardrails；
2. domain-types-and-constants；
3. typed-hardware-access；
4. module-api-boundaries；
5. state-machine-split；
6. parameter-modbus-descriptors；
7. output-isr-split；
8. display-input-cleanup；
9. formatting-and-warning-policy。

## 6. 完成标准

整体计划完成时必须满足：

- 活动固件源码中不再出现反编译命名。
- 业务模块不直接操作未命名裸地址。
- 每个物理地址具有规范名称、宽度和用途说明。
- 公共接口按模块组织，文件私有实现不再暴露。
- state_machine() 和 output_stage() 完成职责拆分。
- 参数、EEPROM 和普通 Modbus 映射由统一描述表维护。
- ISR 写入顺序、协议帧、状态机行为和 SRAM 布局保持等价。
- 构建零警告，格式检查通过。
- 全部既有测试持续通过，新增护栏与结构测试通过。
- 最终实机验证需在用户明确授权后单独执行。
