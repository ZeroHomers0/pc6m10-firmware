## P1：第二路闭环三处反馈复制仍被误写成自赋值

位置：`firmware/src/09_output_stage.c`第576、589、601行。当前三处均为：

```c
*adc_field_output_scaled_ptr = *adc_field_output_scaled_ptr;
```

原BIN三组指令分别位于`0xF44A..F450`、`0xF4B0..F4B6`、`0xF504..F50A`。字面量`[0xF740]=0x100015B8`为源，`[0xF724]=0x100015BC`为目的，应为：

```c
*adc_field_output_scaled_ptr = *adc_voltage_output_scaled_ptr;
```

该提交把PID反馈改为读取0x100015BC是正确方向，但没有同步恢复三处跨单元复制。复现：第二路闭环运行态、ADC给定100、限幅标志1、计数0、0x100015B8=3000、0x100015BC=1；原BIN在PID入口的(目标,反馈)为(526,3000)，当前为(526,1)。关闭内存写hook后仍复现，不是Thumb IT块hook假差异。偏差影响PID内部状态；本样本最终触发输出可能受钳位掩盖，不能据此忽略反馈错误。

扩展24个实际进入控制块的样本，当前4例不同。在临时副本只补齐上述三处复制后，4例全部消除，全部28个输出样本一致。未把临时补丁写回当前工程。

## P2：第二路闭环新增回归未进入被修复分支

位置：`test/emulation/test_audit_fixes_2.py`第141行起的第二路闭环seed。

该样本虽设置output_mode=1、control_mode=1、run_state=5，却未设置`adc_output_reference_ptr(0x100015A8)>=10`。当前初始RAM镜像使该条件不满足，原BIN主控制块入口要求`output_mode==1 && ADC给定>=10`；执行跟踪证实该样本没有进入`0xF30E`，因而不能证明本轮第二路闭环修复正确。修复前版本在此样本也通过。

建议显式设置0x100015A8=100，使用互不相等的电压/电流反馈值，加入标志1与计数0/49/50/51等组合，并断言PID调用确实发生、反馈参数和完整SRAM一致。同时对所有有界仿真调用检查正常返回，防止双方都用尽预算而被误判一致。
