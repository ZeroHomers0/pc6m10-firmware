# LPC1765 固件最优逆向与可编译重建指南（AI 工作规范）

> 文档性质：长期维护的活文档，不是某次进度记录。  
> 适用范围：以 PC6M-10、PC12M-2 为样板，对 LPC1765/Cortex-M3 裸机固件进行备份、
> 反汇编、可读 C 重建、执行级等价验证、构建和分级烧写。  
> 核心原则：**复用方法和工程骨架，不复用未经目标 BIN 证明的地址、位宽、常量或控制流。**

---

## 1. 目标、边界与“完成”的定义

本流程的目标不是得到“看起来像原程序”的伪代码，而是建立一条可以审计、可以编译、可以
逐层验证、可以安全上板的证据链：

```text
目标板原始 BIN
  → 不可变备份与身份确认
  → 原始反汇编/函数边界/引用证据
  → SRAM 数据、全局变量、字符串和查表恢复
  → 可读 C 工程
  → 原 BIN 与新 ELF 的静态 + Unicorn A/B 差分
  → 仅控制电的实机验证
  → 空载波形/通信/标定
  → 低压限流
  → 经授权后才允许带载
```

“反编译完成”至少同时满足：

1. 原始固件有两份独立备份，哈希一致，型号、向量、CRP 状态均已记录。
2. 每个业务函数都能追溯到目标 BIN 的反汇编证据；大函数不能只保留反编译器伪代码。
3. 启动、数据初始化、BSS、栈、向量表、CRP 和关键外设访问均已复建。
4. 关键函数已做原 BIN ↔ 新 ELF 的执行级 A/B；只与手写 Python 模型一致不算等价证明。
5. 构建产物经过向量校验、CRP 检查、尺寸检查和回归测试。
6. 实机验证按风险分级推进，不能用离线 PASS 代替时序、电气和带载证明。

以下情况不能宣称完成：仅能编译、仅能启动、仅通过静态测试、仅主界面显示正常、仅在同一份
错误 C 逻辑上做自测，或只因参考项目行为相似就认定目标板相同。

## 2. PC6M 与 PC12M 给出的最优路线

### 2.1 相同的主干

两项目均采用同一主干：备份 → 反汇编 → 数据层恢复 → 模块化 C 重建 → 静态审计 →
Unicorn A/B → W8 分级实测。源码模块、启动文件、链接脚本、数据镜像、测试框架和工具分类
也基本同构。

### 2.2 不同的实施方式

| 项目 | 实施方式 | 最重要的经验 |
|---|---|---|
| PC6M-10 | 从原 BIN 起步，从零建立工程和验证工具 | 反编译器输出绝不能直接视为正确 C；实机问题会暴露静态审查遗漏 |
| PC12M-2 | 复用 PC6M 成熟骨架，对目标 BIN 做函数级差异迁移 | “孪生项目”仍会改变函数地址、SRAM 符号、CRC 表地址、计数器排列和触发逻辑 |

对于同系列新板，最优方法不是再次从零命名全部语义，也不是复制参考源码后批量替换数字，而是：

1. 用参考项目建立模块边界、已知外设语义和验证框架。
2. 用目标 BIN 重新生成函数表、数据镜像、literal、全局地址和字符串证据。
3. 以调用关系、外设访问、字符串引用、常量和控制流指纹匹配同源函数。
4. 逐函数移植可读结构，但逐项替换目标地址、位宽、常量、分支和循环边界。
5. 对“相同”与“不同”都用目标 BIN 的 A/B 结果证明。

函数地址不能作为跨版本的主匹配键；重新链接或少量函数增删会使后续地址整体漂移。

目录规则：

- 原始反编译、完整反汇编和硬件资料是证据，即使当前没有引用也不得删除。

- 当前流程脚本不得写死开发者机器路径；从脚本位置推导项目根目录。
- 参考项目资产放在 `reference/` 或明确标注“参考”；不能混入目标证据目录冒充目标结果。
- `archive/` 只追溯，不作为 AI 默认入口。

## 4. 分阶段逆向策略与门禁

### P0：现场备份和身份冻结

#### 动作

1. 断开市电、SCR 门极和功率负载，只接控制电。
2. 优先用 SWD 只读探测；SWD 被应用固件复用时，使用 connect-under-reset 或 ISP。
3. 读取完整 256 KiB Flash，至少保存两份到独立物理位置。
4. 计算 SHA-256；再次读取全片或分块抽样，比较字节一致性。
5. 解析并记录：
   - 初始 SP 和 Reset 向量；
   - 前 8 个向量字 LPC 校验和；
   - Part ID/Signature；
   - `0x2FC` CRP 字；
   - 文件大小、读取时间、通道、波特率和日志。

#### 硬门禁

- 未得到两个一致备份前，禁止 `erase`、`unlock`、`recover`、`mass erase`。
- CRP 不是 `0xFFFFFFFF` 时，禁止擅自解除保护；CRP1/2 下 ISP 全局擦除可能允许，但会销毁
  无法读取的原固件，必须取得明确授权。
- 仓库里的旧备份 CRP 状态不能代表板内当前状态，必须读板确认。

#### 输出

`backup/BACKUP_RECORD.md`、原始 BIN、重读/分块文件和完整工具日志。

### P1：建立原始反汇编金标准

#### 动作

1. 以 Cortex-M3、Thumb、小端、Flash 基址 `0x00000000` 导入 BIN。
2. 先从向量表创建 Reset 和全部有效 ISR，再做自动分析。
3. 保存函数清单：入口、长度、调用者、被调用者、字符串、SRAM 和 MMIO 引用。
4. 导出两套证据：未经人工改写的 raw 指令，以及带函数名/xref/literal 注释的 functions。
5. 对状态机、Modbus 分发、输出级等超大函数，直接保存完整指令转储；Ghidra 反编译超时不是
   省略函数的理由。
6. Thumb 函数指针最低位可能为 1；函数实际代码地址和调用时入口状态必须分别处理。

#### 函数匹配优先级

跨固件匹配按以下顺序综合判断：

1. 独特 MMIO 地址和 GPIO 掩码；
2. 调用图和 ISR 向量位置；
3. 字符串/literal/查表引用；
4. 参数数量、循环结构和状态变量集合；
5. 指令相似度；
6. 最后才参考地址邻近关系。

#### 门禁

每个业务函数必须归入：已匹配、目标新增、目标删除或待确认。不得把“没有伪代码”当作空函数。

### P2：恢复数据层和内存语义

#### 动作

1. 识别启动运行库的数据拷贝/解压流程，恢复上电时 SRAM `.data` 初始镜像。
2. 确定 `.bss` 清零范围、最终栈顶、堆栈可能覆盖区域。
3. 收集 DAT_/PTR_ literal 值，但把“地址值正确”和“访问类型正确”作为两个独立问题。
4. 逐次访问检查 `ldrb/strb`、`ldrh/strh`、`ldr/str`，建立 8/16/32 位访问证据。
5. 重建字符串池时保留原编码和簇边界，每簇末尾必须有 NUL；扫描同一源码行的所有调用，
   不能只取第一个正则匹配。
6. 独立提取 CRC、标定、分段除数、状态跳转等表并以已知输入验证表语义。
7. 为 SRAM 地址建立别名表：同一物理地址可能由多个 literal 槽引用；不同固件中的 DAT 名称
   不代表同一物理变量。

#### 跨项目警告

PC12M 已证明：CRC16 表地址与 PC6M 不同；输入消抖计数器的排列和 DAT 符号也不同。复制参考
`globals.c` 后只改少数显眼地址，会制造“能编译但写错相邻字节”的系统性错误。

#### 门禁

- 数据镜像长度、起止地址和哈希可重现。
- 全局符号覆盖率报告无不明大洞。
- 每个非对齐地址的 32 位访问都必须单独解释。
- 字符串调用映射未命中数为 0，或每个豁免都有证据。

### P3：建立最小但正确的可编译工程

#### 启动与链接必须先正确

1. 向量表覆盖目标 MCU 的完整 IRQ 顺序；未实现 IRQ 使用明确 weak handler。
2. 前 8 个向量字低 32 位和必须为 0。
3. `0x2FC..0x2FF` 显式保留 `0xFFFFFFFF`，`.text` 不得占用 CRP 字。
4. Reset_Handler 按目标固件顺序恢复原 `.data`、清原 `.bss`，再初始化新工程自身
   `.data/.bss`。
5. 栈顶使用目标复位向量/运行库证据，不凭“SRAM 顶部通常如此”猜测。
6. 原固件绝对 SRAM 区与新编译器全局区隔离，防止链接器变量覆盖目标地址区。
7. `objcopy --gap-fill 0xFF`，并在构建末尾自动检查大小、向量和 CRP。

#### C 代码恢复顺序

建议从叶函数到核心函数：

1. GPIO/寄存器封装、延时、CRC、字符串映射；
2. I2C、ADC、UART 和输入消抖；
3. 参数加载/同步、Modbus 寄存器读写；
4. 继电器、认证、闭环控制；
5. 外部中断、TIMER ISR 和输出级；
6. 主状态机和 Modbus 大分发；
7. main、Reset 和跨模块整合。

这样可以先建立稳定的叶函数 A/B，再用调用 hook 分段验证大函数。

#### C 还原规则

- MMIO 和异步共享 SRAM 使用 `volatile`；强转后也必须保留 `volatile`。
- 地址加法默认按字节表达：`(uintptr_t)base + offset`，不要让 `T * + offset` 偷偷按元素缩放。
- 位宽以目标指令为准，不以变量名、对齐习惯或参考项目类型为准。
- 有符号性以比较指令、扩展指令、除法指令和边界行为综合判断。
- 保留反编译中看似多余但有外设时序、喂狗、竞态或 ABI 意义的读写。
- 分支必须核对条件标志由哪一条指令产生；相邻的 `sub.w`、`uxtb` 等不一定更新标志。
- 大函数按基本块和地址范围重建，明确 `fall-through`、共享尾部和提前返回。
- 每一处人工修正写短注释，标出目标 BIN 地址或证据文件，而不是只写“修复 bug”。

### P4：逐模块人工审计

对每个模块填写审计矩阵：

| 项目 | 必查内容 |
|---|---|
| 函数覆盖 | 原入口是否都有实现；是否有异常小的空实现/坍缩函数 |
| 控制流 | 条件方向、边界 `<`/`<=`、落空、共享尾、return、循环次数 |
| 数据 | SRAM 地址、别名、读写宽度、有符号性、初始值 |
| 外设 | MMIO 地址、字节偏移、SET/CLR/PIN/DIR、写顺序、写宽度 |
| 调用 ABI | 参数寄存器、返回值是否有效、结果是否通过 out 参数返回 |
| 表与文本 | literal 解引用层级、字符串簇、CRC/跳转表地址和内容 |
| ISR | 清中断顺序、共享状态、连续调用、所有模式分支 |

审计结论必须能链接回反汇编证据。仅比较 C 文件行数或函数名不能证明等价。

### P5：分层验证，而不是一次“全 PASS”

#### 第一层：静态与构建检查

- 无错误、无意外警告；生成 ELF/MAP/BIN/HEX。
- 校验向量、CRP、镜像尺寸、段布局、符号覆盖、字符串和查表。
- 用 ELF map/符号查询新函数地址，测试不得硬编码会随构建漂移的新 ELF 地址。

#### 第二层：叶函数执行验证

原 BIN 和新 ELF 使用相同 SRAM/MMIO 种子，比较：返回值、目标 SRAM、MMIO 写地址/宽度/值/
顺序。先覆盖 GPIO、ADC、I2C、CRC、UART、寄存器读写、消抖和闭环边界。

#### 第三层：状态与中断序列

- 不只测单次调用；覆盖 2/10/多 tick 状态演进。
- 中断连续调用，覆盖清标志、计数回绕和不同输出模式。
- 输入矩阵包含边界值、故障、急停、复位、运行/停止和菜单编辑态。
- 对输出级比较 GPIO/MMIO 写迹，不能只比最终 RAM。

#### 第四层：协议与错误路径

Modbus 至少覆盖 0x03/0x06/0x10、合法/非法地址、非法值、CRC 错、长度错、多寄存器边界、
异常响应、字节序和连续 RX/THRE/RDA 中断。

#### A/B 框架本身的门禁

- 原 BIN 入口以 Thumb 状态执行；新 ELF 地址从符号表动态查询。
- 正确设置 R0-R3 和栈；不能只把内存播种好却忘记参数寄存器。
- 通用播种函数执行后再覆盖目标用例值，防止目标值被后续播种悄悄改回。
- 只比较函数契约：编译器残留的 caller-clobbered 寄存器若调用点立即覆盖，不应制造假失败。
- Unicorn mem-hook 可能报告相同最终行为下的访问粒度伪影；必须结合指令和末态判断。
- 手写模型只能补充语义测试；金标准仍是目标原 BIN。
- 每次修复新增最小回归用例，并证明该用例在 bug 版本上会失败。

#### P5 退出条件

验证清单全部 PASS；所有豁免都写明 ABI/硬件/原厂设计依据；不能以“多数通过”进入烧写。

### P6/W8：实机分级验证

建议固定五级，不跨级：

1. **控制电冒烟**：电流、温升、复位、LCD、按键、看门狗、继电器安全态。
2. **无门极/无负载功能**：菜单、EEPROM、Modbus、ADC 输入、报警和恢复流程。
3. **空载触发波形**：所有通道、顺序、脉宽、周期、电角度、封锁和故障响应。
4. **低压限流**：隔离电源、限流、假负载，验证闭环、软起停和保护。
5. **带载**：仅在前级证据完整、风险评估和用户明确授权后执行。

每一级记录：固件哈希、接线、仪器、输入条件、预期、实测、原始 CSV/照片/日志、判定和回退方案。

## 5. A/B 差分思想与工程实现

### 5.1 A/B 的本质：把原固件当作行为预言机

A/B 不是比较两份源码，也不是要求新 BIN 与原 BIN 字节相同。原厂固件通常由 IAR 编译，
重建工程使用 GCC；两者会有不同的指令选择、寄存器分配、函数地址、常量池和基本块排列。

A/B 要回答的是：

> 在相同初始 CPU、SRAM 和外设输入下，目标原 BIN（A）与重建 ELF（B）是否产生相同的
> 可观察业务行为？

标准模型为：

```text
A = 目标板原始 BIN 中的函数或执行片段
B = 当前重建 ELF 中的对应函数或执行片段
S = 完全相同的初始状态与输入种子
O = 事先定义的可观察结果集合

run(A, S) → Oa
run(B, S) → Ob

Oa == Ob  才能说明该用例在观察边界内等价
```

这里的关键不是执行两遍，而是事先定义 `S` 和 `O`。如果输入没有播种完整，或观测面漏掉了
关键 GPIO 写迹，即使显示 PASS 也可能是假等价。

### 5.2 为什么不能只做三种传统验证

| 验证方式 | 能证明什么 | 单独使用的缺口 |
|---|---|---|
| 源码审查 | C 代码看起来合理、可读 | 可能忠实实现了错误理解 |
| 与手写模型比较 | 符合分析者预期 | 模型和 C 可能共享同一个误解 |
| 新固件单体测试 | 新 ELF 在给定输入下自洽 | 不能证明原固件也是这个行为 |
| 原 BIN ↔ 新 ELF A/B | 目标行为在指定观察面是否一致 | 仍不能证明未覆盖状态和物理时序 |

因此最优组合是：静态反汇编证据确定原因，A/B 执行证明行为，手写模型检查协议/数学语义，
实机仪器验证模拟器无法表达的电气与时间约束。

### 5.3 每个 A/B 用例先写“函数契约”

在写断言前，先描述被测函数的输入和可观察输出：

```text
函数：adc0_wait_done
输入：AD0GDR/AD0DR0 的寄存器值
输出：返回的 12 位 ADC 值
副作用：允许的 MMIO 读；无目标 SRAM 写
停止条件：函数正常返回
不比较：caller-clobbered 寄存器的残留值
```

不同类型函数的推荐观察面：

| 函数类型 | 必比项目 |
|---|---|
| 纯计算/CRC | 返回值、输入缓冲是否被意外修改 |
| 参数/状态函数 | 目标 SRAM 字节末态、写地址和写宽度 |
| GPIO/外设叶函数 | MMIO 写地址、宽度、值、顺序；必要时包含读序列 |
| ISR | 清中断、连续调用后的 SRAM/MMIO 轨迹、计数回绕 |
| 状态机 | 多 tick 的状态末态、子调用轨迹、显示/GPIO 参数序列 |
| 协议分发 | TX 帧、长度、CRC、异常码、状态和缓冲区末态 |
| 延时/位时序 | 指令结构和循环次数；最终再用示波器测物理时间 |

禁止为了快速通过而直接比较“全部寄存器 + 全部内存”。过宽的观察面会被编译器临时寄存器污染；
过窄的观察面又会漏掉写错相邻地址、写序改变等真实问题。观察边界必须来自调用 ABI、硬件副作用
和业务契约。

### 5.4 相同输入状态的构造

一条可靠用例按固定顺序构造：

1. 为 A、B 创建相互隔离的新模拟器实例。
2. 映射相同 Flash、SRAM、外设页和栈；分别装载原 BIN、新 ELF。
3. 写入相同的原始 SRAM 初始镜像。
4. 执行通用零值/默认值播种。
5. **最后**写入本用例的目标值和边界值，避免被通用播种覆盖。
6. 设置相同 R0-R3、SP、LR、xPSR/Thumb 状态和需要的 MMIO 输入。
7. 安装相同 hook 和停止条件，再分别执行。
8. 对结果进行规范化后比较，并保存首个差异及上下文。

建议让播种器返回结构化快照，并在执行前断言关键种子确实存在。例如测试 ESTOP 边界时，进入
函数前先断言 ESTOP 等于目标值，防止出现“用例名字测试 ESTOP=2，实际被默认播种成 1”的假一致。

### 5.5 差异比较的三个层次

#### 末态差分

比较函数返回后的返回值、SRAM 和外设最终值。适合纯计算、参数同步和寄存器映射，但可能漏掉
“先输出危险脉冲、后恢复安全态”的问题。

#### 写迹差分

记录每次写的 PC、地址、宽度和值，按顺序比较。GPIO、SCR、继电器、UART、I2C、LCD 和 ISR
必须使用写迹；最终值相同不代表中间硬件行为相同。

#### 调用序列和多 tick 差分

对大状态机 hook 子函数入口，比较每个 tick 的调用和参数，再连续执行多个 tick 比较状态演进。
这能捕获漏调用、调用提前/延后、错误 `return`、刷新节拍改变和闪烁块丢失。

三层应由小到大推进：叶函数末态 → 叶函数写迹 → 大函数调用序列 → 多 tick 全状态矩阵。

### 5.6 用例矩阵设计

每个维度至少覆盖：正常值、零值、上下边界、边界外一位、状态转换前后和错误输入。推荐采用
“笛卡尔积 + 定向反例”，而不是只测几个正常样例。

```text
输入消抖：引脚高/低 × 计数器 0/阈值-1/阈值/阈值+1 × 锁存状态
状态机：MENU × MENU2 × MENU3 × key × FAULT × RUN × 多 tick
输出级：运行模式 × 控制方式 × 故障 × 软起停状态 × 触发相位
Modbus：功能码 × 地址边界 × 数量 × 值边界 × CRC/长度/站址有效性
闭环：正/负/零误差 × 死区 × 分段边界 × 上下钳位 × 通道
ISR：输出模式 × 当前计数 × 回绕边界 × 连续调用次数
```

发现 bug 后，除了把它加入大矩阵，还要建立一个最小定向用例。例如 ADC 指针偏移 bug 的用例
应给 AD0GDR 和 AD0DR0 写入不同已知值，保证错误地址不可能碰巧返回相同结果。

### 5.7 差异出现后的判定流程

```text
发现 Oa != Ob
  ↓
确认输入种子、入口、Thumb、参数和停止点相同
  ↓
定位首个差异：返回值 / RAM / MMIO / 调用序列
  ↓
回看双方首个分叉位置的反汇编和调用点
  ↓
分类：真实移植 bug / 原厂设计差异 / ABI 非契约 / 模拟器伪影 / 用例错误
  ↓
真实 bug：修源码 + 最小回归 + 全矩阵
非 bug：写明证据后做最小范围规范化或豁免
```

豁免必须满足三个条件：说明为什么调用者不消费该差异、为什么不会形成外设或持久状态副作用、
以及用什么反汇编/调用点证明。PC12M `run_stop_preset` 的 R0 残留就是 ABI 非契约示例：IAR 和
GCC 返回时 R0 不同，但调用点立即调用下一函数覆盖 R0，真实契约是 SRAM 末态。

禁止使用以下方式“修绿”：

- 对整个 SRAM 做大范围忽略；
- 删除失败状态或边界用例；
- 不分析就忽略全部寄存器/MMIO 差异；
- 让 A、B 共用会被一侧修改的内存对象；
- 用新 ELF 结果反向修改期望值，替代原 BIN；
- 仅因参考项目也这样写就判定目标正确。

### 5.8 PC6M/PC12M 的四路对照

同系列迁移时实际存在四个对象：

```text
6A  = PC6M 原 BIN       6B  = PC6M 重建 ELF
12A = PC12M 原 BIN      12B = PC12M 重建 ELF
```

正确关系是：

- `6A ↔ 6B`：证明六相重建等价。
- `12A ↔ 12B`：证明十二相重建等价。
- `6A ↔ 12A`：用于发现产品差异，**不要求相等**。
- `6B ↔ 12B`：用于检查源码迁移范围，**不能代替各自原 BIN 的 A/B**。

跨项目差分应先建立函数映射，再比较控制流、SRAM/MMIO 引用和输出轨迹。六相与十二相在触发
通道和时序上的差异应被保留；如果为了让 `6B == 12B` 而抹平差异，反而破坏目标固件真实性。

### 5.9 A/B 能证明什么、不能证明什么

A/B PASS 的严格含义是：已执行用例、已定义观察面、当前模拟器模型内未发现差异。它不能证明：

- 未覆盖输入和长时间状态一定等价；
- 模拟器未建模的外设时序一定正确；
- GCC 指令周期与 IAR 完全相同；
- 模拟的 ADC、UART、EEPROM 或中断竞争符合真实电气条件；
- SCR 带载安全。

因此 A/B 是上板前最重要的软件证据，但不是上板和示波器验证的替代品。P5 全过后仍必须按 W8
从控制电、空载触发、通信标定、低压限流逐级推进。

### 5.10 回归资产和输出格式

每个 A/B 模块应输出稳定、可审计的摘要：

```text
模块：STATE_MACHINE_MATRIX
目标：original.bin SHA-256 / firmware.elf build SHA-256
函数：A 入口 / B 符号与解析地址
矩阵：维度与用例数
观察面：返回值 / SRAM 范围 / MMIO / 子调用
结果：PASS n/n，或首个 FAIL 的种子和差异
豁免：地址、原因、调用点证据
```

修复闭环必须做到“先红后绿”：保留能在历史 bug 版本稳定失败、在修复版本通过的用例。只有在
当前版本跑绿，不能证明测试真正覆盖了问题。

## 6. 已暴露问题与强制回归护栏

下表来自 PC6M 实际修复和 PC12M 差异迁移，不是理论风险清单。

| 已暴露问题 | 根因 | 以后必须加的护栏 |
|---|---|---|
| ADC 等待死循环，LCD 周期闪屏、按键失效 | `uint32_t * + 4` 被编译成地址 `+16`，误读 AD0DR0 而非 AD0GDR | 每个 MMIO 字节偏移检查生成指令；给正确/错误寄存器播不同值做 A/B |
| 背光不亮、全部按键无效 | FIO 基址指针 `+0x34` 被按 32 位元素缩放 | 禁止用带类型指针表达寄存器字节偏移；输入引脚全组合 A/B |
| GPIO/SCR 写被合并或重排 | 强转为非 volatile 指针，剥离 `volatile` | 对关键函数比较完整 MMIO 写迹，不只比最终值 |
| 连续 byte 参数互相污染 | `ldrb/strb` 槽被生成为 `uint32_t *` | 自动比对反汇编访问宽度；非对齐 word 访问零容忍审计 |
| PID 负误差触发错误钳位 | 有符号中间量误作 `uint32_t` | 正/负/零误差和上下钳位 A/B；检查 `sdiv` 与有符号条件码 |
| Modbus 读响应恒为 0 | 误信函数返回值，原函数实际通过 out 参数输出 | 在调用点继续跟踪返回寄存器和内存回读；协议真执行测试 |
| Modbus 16 位字段错序 | 把线协议大端字段写成小端拼接 | 使用真实帧字节测试 0x03/0x06/0x10，断言响应和 CRC |
| CRC 循环次数曾被误判 len-1 | 错判 `bne` 所用的条件标志来源 | 对 0/1/多长度做原 BIN A/B，并逐指令确认置标志指令 |
| 恢复出厂页只显示 “M” | `ldr r0,[literal]` 的池值被误当成字符串地址本身 | literal 必须区分“槽地址”和“槽内值”；字符串首字节/终止符检查 |
| 菜单编辑不闪烁 | 反编译漏掉 TIMEOUT 回绕后的擦除基本块 | 超大状态机按地址范围核对；多 tick 验证显示调用序列 |
| 所有菜单项同时高亮/复位文字不可见 | 调用参数、行列和属性被默认化 | hook 显示函数，比较字符串、行、列、属性四元组 |
| 控制方式从上限错误环绕 | 枚举钳位被泛化成环绕；不同 item 语义并不一致 | 每项边界值 × 上下键矩阵，不共享未经证明的通用逻辑 |
| 故障时首页输入处理失效 | 三个 DISP_SEL 分支错误嵌套进 FAULT 门控 | 状态机必须覆盖故障态多 tick 和调用轨迹 |
| 主循环输入扫描时机改变 | 为追求可读性移动调用，破坏原状态机调用节拍 | 比较跨 tick 调用轨迹；公共调用不得脱离原基本块位置 |
| Modbus 非法帧未返回正确异常 | 分发尾部和异常响应基本块在大函数重建时被遗漏 | 错 CRC、错长度、非法地址/值均做真执行测试并检查完整响应 |
| UART RX 组帧曾为空实现 | 大函数/未知函数被当作可忽略 stub | 函数覆盖审计抓“原函数很大、新函数仅几字节”的坍缩 |
| 关键延时被 `-Os` 删除 | 空循环无可观察副作用 | `volatile` 循环 + 反汇编结构测试；物理时序最终以示波器为准 |
| 向量后半段外设顺序错误 | 套用错误 IRQ 表 | 使用目标 MCU 官方向量顺序，并审计 IRQ0..末项 |
| 看门狗喂狗序列、定时器复位步骤缺失 | 伪代码省掉常量写或初始化中间态 | 启动叶函数逐指令核对；断言 WDFEED 0xAA→0x55 和 TCR 复位顺序 |
| 认证放行分支方向写反 | 误读 `cbz/cbnz` 跳转目标及标志语义 | 同时覆盖成功/失败/锁机路径；结合认证函数写入值反证变量语义 |
| 原镜像栈顶和链接栈顶不一致 | 从错误线索推断最终 SP | 以目标向量和启动运行库为证据；做栈水位实测 |
| 字符串漏映射 | 生成脚本每行只匹配第一个调用 | `findall` 全量扫描；所有常量显示调用未映射数必须为 0 |
| flash 常量被写成 `&DAT_xxx` | 反编译器把立即数字面量误命名成 SRAM 符号 | 对 `movw/movt/adr/ldr literal` 分别判义，检查新 ELF 实参值 |
| PC12M closed-loop 写错输出槽 | 同系列变量别名/地址直接继承 | 比较目标 BIN 写地址；同物理地址别名与不同物理槽分开建表 |
| PC12M 消抖计数器错位两字节 | 复制了六相 DAT 对应关系，目标排列不同 | 每个消抖函数分别抓高/低沿写地址，不按函数顺序推断 |
| PC12M CRC 表地址沿用六相地址 | 表内容相似造成假安全感 | 从目标 CRC 函数 literal 反推表地址，再用已知帧验证 |
| A/B 出现寄存器或 hook 假差异 | 比较了非契约残留寄存器，或模拟器 hook 粒度不同 | 先定义函数契约；结合调用点、末态和指令判定豁免 |
| A/B 用例“假一致” | 标准播种在目标播种后覆盖了目标值 | 固定播种顺序，并让回归在历史 bug 版本上先红后绿 |

还必须区分三类结论：

- **移植/反编译 bug**：目标 BIN 与新 ELF 不一致，必须修复。
- **原厂设计或原厂缺陷**：目标 BIN 与新 ELF 一致；若要改善，必须作为独立功能变更，不能伪装成逆向修复。
- **验证伪影**：模拟器/编译器/ABI 造成的非契约差异；必须记录依据，不能简单删除断言求绿。

环境确认：

```powershell
arm-none-eabi-gcc --version
```

## 8. 备份与烧写标准作业

本节给出决策和最小命令；PC6M 的具体接线、脚位和完整命令以根目录 `操作文档.md` 为唯一源。

### 8.1 通道选择

1. SWD 能连接：使用仓库版 `tools/jlink/JLink.exe`，100 kHz 起步。
2. 应用固件复用 SWDIO/SWCLK：尝试 connect-under-reset。
3. SWD 仍不可用：ISP 只读识别/备份；必要时 ISP 擦除解困，再回 SWD 高速烧写。
4. 不要因为 4000 kHz 失败就判断芯片/探针损坏；PC6M 实测根因曾是四根主线接触不良。

### 8.2 SWD 只读探测

```powershell
.\tools\jlink\JLink.exe -CommanderScript tools\jlink\check.jlink
```

成功应看到 Cortex-M3 和 SW-DP；烧写前再次保存完整 Flash 并读取 `0x2FC`。

### 8.3 SWD 烧写

```powershell
.\tools\jlink\JLink.exe -CommanderScript tools\jlink\flash.jlink
```

脚本顺序必须保持：`connect → savebin → mem32 0x2FC → erase → loadbin → verifybin → reset/go`。
没有 `Verify successful` 不能判定成功。烧写后检查 CRP，并用 `runcheck.jlink` 确认 PC 位于用户
Flash、初始化标志存在、MEMMAP 正确。

### 8.4 ISP 解困

- UART0 TX/RX 交叉、共地；复位时 P2.10 拉低进入 Boot ROM。
- PC6M 的 UART0 网可能受 ADM2483 接收输出驱动，必要时断隔离侧供电或禁用接收输出。
- 9600 波特整片 256 KiB 极慢；ISP 适合识别、读小区和擦除解困，随后转 SWD。
- 器件识别成功不等于编程成功，必须看到编程完成和 Verify。

Flash Magic 命令行程序是 `fm.exe`，不是 GUI `FlashMagic.exe`。典型只读动作：

```powershell
fm.exe --device LPC1765 --crystalfreq 12 --serialport COM7 --baudrate 9600 --readsignature
fm.exe --device LPC1765 --crystalfreq 12 --serialport COM7 --baudrate 9600 --read="0x2FC,0x300,crp.hex"
```

COM 口必须按现场枚举结果替换；没有一致备份和明确授权，不得执行 `--erasedevice`。

### 8.5 复位陷阱

J-Link 驱动 nRESET 后，应用固件可能立刻复用 SWD 脚并造成调试状态干扰。最终运行确认优先使用
物理断电再上电；不能把“J-Link 会话里 go 后的状态”当作唯一实机证据。

## 9. AI 执行规范

### 开始任务前

1. 完整阅读目标项目 `AGENTS.md`，再读 `DOCUMENTATION_INDEX.md` 和当前状态文档。
2. 检查 `git status`；用户已有改动不得覆盖或清理。
3. 确认目标 BIN 路径、大小和哈希；目标 BIN 缺失时，可以整理结构和写工具，但不能完成 A/B。
4. 先列证据缺口，再决定是否参考同系列项目。
5. 对会擦除、烧写、解除保护或带载的动作执行授权门禁。

### 分析和修改时

- 每个事实标为：目标 BIN 证据、硬件证据、参考项目推断、待验证。
- 优先用 `rg`、生成报告和脚本批量检查；机械修改脚本必须幂等。
- 不根据函数名或 DAT 名猜位宽；始终回到目标指令。
- 不删除“当前没用”的反汇编和硬件证据。
- 不把 PC6M 地址、栈顶、CRC 表、SRAM 符号或测试种子直接带入新板。
- 不为让测试通过而扩大掩码、删除断言或跳过失败模块；先证明差异是否属于契约。
- 发现原厂设计问题时先记录，不擅自改变行为。
- 修复后新增能稳定复现旧问题的回归测试，并跑相关测试和全量入口。

### 每阶段汇报格式

```text
阶段：P?/W8-?
目标 BIN：路径、大小、SHA-256
输入证据：反汇编文件/地址范围/硬件资料
本次修改：文件和语义
发现差异：目标原行为 / 新工程旧行为 / 修复后行为
验证：命令、用例数、PASS/FAIL、豁免依据
风险：尚未覆盖的状态、时序或硬件条件
下一步：唯一可执行动作
```

### 提交前

1. `git diff --check`。
2. 文档链接和脚本路径存在；索引同步。
3. 构建、相关回归、全量测试、A/B 主入口按改动风险执行。
4. `git status` 只包含本任务文件。
5. 提交信息说明“证据 + 修复 + 验证”，不只写“优化/调整”。
6. 推送属于外部写操作，按用户授权执行。
