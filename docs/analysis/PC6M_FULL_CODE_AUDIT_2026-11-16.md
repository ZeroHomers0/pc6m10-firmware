## 2. 已确认问题

### A01 P1：8个校准单写寄存器遗漏下限校验

位置：`firmware/src/08_modbus_dispatch.c` 的0x101B/0x101C/0x101D以及0x1033..0x1037分支（约249行、322行起）。

原版仅接受3500..4500。以0x101B为例：原指令0xCD48..0xCD5A同时检查 `<0x1195` 和 `>0x0DAB`，不满足则发异常响应。当前源码只检查 `write_value >= 4501`，因而错误接受0..3499，并写入校准槽。

扩展矩阵在这8个寄存器各得到28个反例，共224例。写0时原版保留校准值且回复异常5字节，当前写0并回复成功8字节。ADC计算使用校准槽作为除数，错误接受0可能影响换算；这是代码层面的风险分析，未在硬件上试写0。

应恢复原版双边界，而不是把所有写入途径一律限制为3500..4500：0x10表写属于另一条原厂协议路径，必须单独按原BIN判断。

### A02 P1：远程给定0x1028遗漏1000上限

位置：`08_modbus_dispatch.c` 约298行。源码注释“无范围”与证据相反。

原指令0xD49C..0xD4A4执行 `cmp r0,#0x3e8; bhi ...`，接受0..1000；当前直接赋给0x10001788。矩阵有9个超限反例，例如3499原版异常，当前成功。后续输出级虽另有部分钳位，也不能据此省略协议校验。

### A03 P2：0x1018/0x1019未完整重装活动PID增益

位置：`08_modbus_dispatch.c` 约228、236行。

原版写入第4组参数后，按当前组号1..4重新复制**两个**活动增益，原指令0xC9F0..0xCA4E（0x1018）及相应0x1019分支。当前只在组号4时复制本次修改的一个分量。

原始数据镜像初态下，组号1写第4组参数1，OLD活动增益变成80/60，NEW仍20/20；矩阵共30个反例。正常初始化后的活动增益若恰已一致，此差异可能被掩盖；组号切换或活动槽滞后时同步行为仍与原版不同。建议覆盖组号1..4及两个分量初始不一致的情况。

### A04 P2：0x1025/0x1026应答后的看门狗重启等待被省略

位置：`08_modbus_dispatch.c` 约284、288行。

原版写0：0x1025清故障并应答后停在0xD2B8自跳，等待看门狗；0x1026先应答，再清EEPROM 5/6，然后停在0xD388自跳。当前两者均返回；0x1026还把EEPROM写放在应答前。

完整帧执行中，原版两个用例均不正常返回，当前返回。这里的原版非返回是反汇编明确的设计，不应简单作为“超预算”忽略。恢复出厂标记写入后的生效时机、主循环是否继续执行会因此不同；没有找到此偏离的授权记录。

### A05 P2：初始密码页入口遗漏60秒计数和刷新清零

位置：`07_state_machine.c` 约341行，`KEY_INITIAL_PARAMETER_PASSWORD`分支。

原指令0x4C04..0x4C0E把0x10001760置60、0x10001768清0；当前只改页号、选项及空闲计数，遗漏上述两项。

合法复现：进入前倒计时27、刷新73，按0x0E后OLD为60/0，NEW仍27/73。初态为0时，随后倒计时递减可能下溢，造成退出时机异常。跳过显示与完整执行显示均复现，排除显示替身影响。

### A06 P2：初始参数页快加/快减分支不可达

位置：`07_state_machine.c` 约566行。

外层只接受KEY_DOWN/KEY_UP（2/3），内层虽写KEY_FAST_UP/KEY_FAST_DOWN（0x16/0x21），但永远进不去。原指令0x58A8起的编辑处理独立接受2/3/0x16/0x21。

在页0x63、编辑态、标定值4000时：0x16让OLD变4001而NEW不变；0x21让OLD变3999而NEW不变。OLD还将刷新计数置250后本帧增至251，NEW没有相应刷新。两种显示执行模式均复现。

### A07 P2：两个密码错误分支的延时循环与状态副作用不等价

位置：`07_state_machine.c` 约500、534行，case0x0A与case0x62。

原版外层先清0，循环10000次；每次有1000次内层空转，结束后喂狗并递增外层。当前改成1000次喂狗/累加外层，遗漏外层清零与实际内层循环，且仅清内层变量。代码注释声称外层至10000，但实现未做到。

复验仅加速原BIN纯空转内层，保留真实外层判断和喂狗：两个页面OLD最终 `(outer,inner,feed_count)=(10000,1000,10000)`，NEW为 `(1077,0,1000)`（外层初值77）。显示返回页面相同不能证明延时等价。

同文件已有正确结构的 `delay_for_password_feedback()`，但这两个分支没有使用它。此次只指出问题，没有替换调用。

### A08 P3：初始参数页退出多出提前return

位置：`07_state_machine.c` 约564行。

原版0x5790..0x57A4在切回主屏、调用splash后继续本帧的尾部；当前立即return。初态空闲/闪烁计数均为0时，OLD退出后为1/1，NEW为0/0。

此项主要是帧尾副作用差异，优先级低于前述问题。原厂续行未必是更好的界面体验，但若决定保留新行为，应明确列为有意偏离而非等价。

- 审计脚本：`tools/audit/full_review_2026-11-16/`。从仓库根目录运行，使用现有Python/Unicorn及Arm工具链；脚本只读现有BIN/ELF，不编译、不连接硬件、不改业务源码。
